## 2. Постановка задачи и контекст

Опишите:

1. **Предметную область и задачу:**
   - Банковская сфера, управление оттоком клиентов.
   - Бинарная классификация с вероятностным выходом.
   - Пользователь: менеджер отдела удержания / маркетолог-аналитик
   - Пользователь выгружает актуальную базу клиентов (CSV-файл) и загружает её в сервис. Через несколько секунд получает тот же файл, но с дополнительными колонками: вероятность оттока, метка риска, ключевая причина оттока
   - На основе этого файла менеджер формирует точечные предложения

2. **Формулировку задачи в терминах ML/ИИ:**
   - Входные данные: табличные данные о клиентах банка (CSV)
   - Целевая переменная: бинарный признак (ушел/не ушел)
   - Выход модели: вероятность оттока в диапазоне \[0,1\]

   - Требования: 
   - Интерпретируемость: Возможность объяснить причины оттока (SHAP-значения)
   - Точность: ROC-AUC > 0.85, Recall по классу "ушедшие" > 0.60
   - Надёжность: Сервис должен корректно обрабатывать ошибки и невалидные входные данные

3. **Целевые метрики качества:**
   - Метрики: ROC-AUC (общая оценка разделения на классы), recall (Критически важно: бизнес хочет найти как можно больше уходящих клиентов), precision (точность), F1 (для сравнения моделей), accuracy (общее качество классификации)

## 3. Данные

Опишите, какие данные использует проект:

1. **Источник данных:**
   - открытый датасет Churn Modelling: https://www.kaggle.com/datasets/shrutimechlearn/churn-modelling

2. **Структура данных:**
   Исходные признаки (10 колонок):
   - CreditScore (int) – кредитный рейтинг (350-850)
   - Geography (categorical) – страна (France, Germany, Spain)
   - Gender (categorical) – пол (Male, Female)
   - Age (int) – возраст (18-80)
   - Tenure (int) – количество лет в банке (0-10)
   - Balance (float) – баланс счета
   - NumOfProducts (int) – количество продуктов банка (1-4)
   - HasCrCard (int) – наличие кредитной карты (0/1)
   - IsActiveMember (int) – активность клиента (0/1)
   - EstimatedSalary (float) – предполагаемая зарплата
   - Целевая переменная: Exited (0 – остался, 1 – ушёл)

3. **Предобработка и EDA:**
   - Доля ушедших клиентов (Exited = 1) составляет 20.4%, что говорит об умеренном дисбалансе классов. Первичный анализ показал отсутствие пропусков в исходных данных. 
   - В распределении CreditScore было замечено аномальное количество клиентов со значением 850. Это может указывать на особенность данных (например, "потолок" рейтинга или синтетическое происхождение), но не является выбросом.
   - На основе исходных данных были созданы новые признаки для улучшения предсказательной способности модели: 
      - Tenure_Ratio (Лояльность = Tenure / Age).
      - Balance_Per_Product (Средний баланс на продукт = Balance / (NumOfProducts + 1)).
      - Active_Senior (Активный пожилой клиент: (Age > 50) & (IsActiveMember == 1)).
      - Has_Balance (Есть ли баланс > 0).
      - Is_Multi_Product (Есть ли 3 или более продуктов).
      - Gender_Male (Пол закодирован как 0/1).
   - На основе проведенного анализа были сделаны следующие ключевые выводы по каждому признаку:
      - Возраст (Age): Один из самых сильных признаков.
      - Баланс счета (Balance): Неочевидный, но важный фактор.
      - Количество продуктов (NumOfProducts): Сильный признак.
      - Активность клиента (IsActiveMember): Активные уходят реже
      - Пол (Gender): Женщины уходят значительно чаще
      - Кредитный рейтинг (CreditScore): Не играет роли
      - Зарплата (EstimatedSalary): Практически не влияет на отток.
      - Наличие кредитной карты (HasCrCard): Не влияет на отток.
      - Стаж (Tenure): Слабое влияние.

## 4. Модели и подходы

Опишите, какие модели вы пробовали и как развивался ваш подход:

1. **Базовые (baseline) модели:**
   - Logistic Regression (без учёта дисбаланса)
   - Baseline без учёта дисбаланса показал низкий Recall (41%) – модель находит только 41% уходящих клиентов.

2. **Улучшенные модели и эксперименты:**
   - XGBoost Default: Простой бустинг без подбора гиперпараметров (ROC-AUC=0.854, Recall=0.450, F1=0.556)
   - XGBoost с GridSearch: Улучшенная базовая модель с помощью подбора гиперпараметров (ROC-AUC=0.859, Recall=0.442, F1=0.562)
   - XGBoost с scale_pos_weight (3.91): Бустинг с взвешенными классами (ROC-AUC=0.865, Recall=0.621, F1=0.580)
   - MLP Default: Базовая нейросетевая модель (ROC-AUC=0.854, Recall=0.440, F1=0.554)
   - MLP с sample_weight: нейросетевая модель с взвешенными классами против дисбаланса (ROC-AUC=0.855, Recall=0.767, F1=0.573)
   - CatBoost Default: Еще один бустинг с взвешенными классами, без подбора гиперпараметров (ROC-AUC=0.852, Recall=0.680, F1=0.635)
   - **CatBoost с GridSearch** (лучшие параметры): Бустинг с подбором гиперпараметров (ROC-AUC=0.857, Recall=0.690, F1=0.643)

3. **Нейросетевые модели (если применимо):**

   MLP (Multi-Layer Perceptron) (notebooks/04_models_MLP.ipynb):

   - Архитектура: 64 - 32 - 16 нейронов
   - Активация: ReLU
   - Оптимизатор: Adam
   - Регуляризация: L2 (alpha=0.001)
   - Early stopping: validation_fraction=0.1, patience=50

Особенности обучения:
   - Учёт дисбаланса через sample_weight
   - Batch size: 32
   - Learning rate: 0.001 (adaptive)

## 5. Экспериментальный протокол и результаты

Здесь важно показать, что выбор финальной модели был осмысленным.

1. **Экспериментальный протокол:**
   - Разделение данных: Train/Test - 80/20 со стратификацией (stratify=y)
   - Метрики: Accuracy, Precision, Recall, F1-Score, ROC-AUC
   - Оценка: На тестовой выборке (2000 записей, 20.35% оттока)

2. **Сравнение моделей по метрикам:**

| Модель | ROC-AUC  | Recall  | Precision | F1  | Accuracy | Комментарий |
|--------|-----------|----------|-----------|------|----------|--------------|
| **catboost_default_v1** | **0.8613** | 0.7371 | 0.4975 | 0.594 | 0.795 | Отличный AUC, но Precision низкий |
| **catboost_gridsearch_balanced** | 0.8614 | 0.6904 | **0.5631** | **0.6203** | 0.828 | Лучший баланс Precision/Recall, высокий F1 |
| **xgboost_default_v1** | 0.8577 | 0.7322 | 0.4942 | 0.590 | 0.793 | Хороший Recall, слабый Precision |
| **xgboost_gridsearch_balanced** | 0.8589 | 0.4398 | 0.7649 | 0.558 | 0.8585 | Высокая точность, но очень низкий Recall — **плохо для банка** |
| **Bank_Churn_MLP** | 0.8555 | **0.7666** | 0.4575 | 0.573 | 0.767 | Лучший Recall, но очень низкая Precision |
| **baseline_logreg** | 0.8213 | 0.6903 | 0.8043 | 0.723 | 0.852 | Простая, но хорошая точность, хуже AUC |


3. **Выбор финальной модели:**
   **Лучшая модель: `catboost_gridsearch_balanced`**

   1. **Самый высокий F1 (0.6203)** — лучший баланс между полнотой и точностью.
   2. **Высокий ROC-AUC (0.8614)** — лучше всех различает классы.
   3. **Лучший Precision (0.5631)** среди CatBoost/XGBoost с хорошим Recall — меньше ложных тревог.
   4. **Accuracy 0.828** — стабильный результат.
   5. GridSearch + balanced — учитывали дисбаланс классов (важно для банковских данных).

   **Trade-off:** Немного уступает XGBoost по ROC-AUC (0.859 и 0.862).

## 6. Архитектура решения и сервис

Опишите, как из модели получился работающий сервис:

1. **Архитектура пайплайна:**
   - Загрузка (CSV/JSON) - Предобработка (preprocessor.py) - Модель (CatBoost) - Результат (CSV/JSON) - Дополнительно SHAP интерпретация

2. **API и endpoints:**
   - `/health` - проверка работы сервиса
   - `/predict` - предсказание для одного клиента
   Пример использования: 
   ```bash
   curl -X 'POST' \
   'http://localhost:8000/predict' \
   -H 'accept: application/json' \
   -H 'Content-Type: application/json' \
   -d '{
    "CreditScore": 650,
    "Age": 35,
    "Tenure": 5,
    "Balance": 50000,
    "NumOfProducts": 2,
    "HasCrCard": 1,
    "IsActiveMember": 1,
    "EstimatedSalary": 50000,
    "Geography": "France",
    "Gender": "Male"
      }'
    ```
   - `/predict_batch` - предказание для нескольких клиентов (CSV файл)
   Пример использования:
   ```bash
   curl -X 'POST' \
   'http://localhost:8000/predict_batch' \
   -H 'accept: application/json' \
   -H 'Content-Type: multipart/form-data' \
   -F 'file=@synthetic_data.csv;type=text/csv'
   ```

3. **Технологический стек:**
   - API - FastAPI
   - Модель - CatBoost
   - Эксперименты - MLflow
   - Контейнеризация	- Docker, Docker Compose
   - Тестирование - pytest
   - Логирование - Python logging
   - Валидация	- Pydantic
   - Запуск сервиса:
   ```bash
   # Локально
   uvicorn src.service.main:app --host 0.0.0.0 --port 8000
   # Docker
   docker-compose up -d
   ```
